改了什么，为什么

现版本改法
标题栏只写 Detail标题栏承担身份：⬡ Pod · ns / name。多开 Detail 时靠标题栏和任务栏区分，否则三个窗口都叫 Detail。
头部三行 + Overview 区块把 Kind / Name / Namespace / Created 各写两遍身份进标题栏，状态进生命体征带，Created / UID / Context 沉到右栏底部的 IDENTITY。同一事实只出现一次。
UID 全长 36 字符占据头部第三行截断为 0f86419f…2820a 加复制按钮。UID 只在确认删除和排查孤儿资源时需要精确值。
Tab 行之外还有一行 Delete / View logs / Exec shell / Edit YAML后三个和 Tab 完全重复，删掉。只留一行 Tab，右侧放 ⋯ Actions ▾ 和 Delete…。省一整行，也消除「点哪个」的歧义。
Status Running 是普通文本，混在 KV 列表里提升为生命体征带首位，带颜色和形状（● / ▲ / ✕）。状态是打开 Detail 的第一目的。
Pod 没有容器、重启次数、就绪数、节点、IP、QoS、conditions、events补齐。CONTAINERS 表是 Pod Detail 的主体——镜像、状态、重启、上次退出码全在这里。
单栏，右侧 60% 宽度空着宽度 ≥ 760px 时两栏：左「现在怎么样」（容器 / conditions / 事件），右「它是什么」（owner / 调度 / 网络 / labels / 身份）。窄于此自动落回单栏。
7 条 label 各占一整行chip 换行排布，默认显示 4 条 + +3 ▾，附「复制为 selector」。annotations 默认折叠。
Owner References 是一行死文本改成可点的 owner chain：Deployment → ReplicaSet → 本 Pod，o 键上跳。这是 Pod Detail 里最高频的跳转。
SelectableLabel 让每个 KV 带自己宽度的高亮块，视觉参差改用 egui::Grid：标签列定宽右对齐留白，hover 高亮整行。文本仍可选中复制，但不再产生锯齿状色块。
失败时无从下手非健康状态下左栏顶部插入 WHY IT'S FAILING：退出码、原因、以及一键进「上一次容器日志」。

区块顺序规则

规则说明
状态优先于身份先回答「它现在怎么了」，再回答「它是什么」。身份信息不会变，状态每秒都在变。
异常上浮资源不健康时，失败原因区块插到左栏最顶部；健康时该区块不存在，不留空占位。
机器写的内容默认折叠annotations、tolerations、finalizers、managedFields——需要时展开，不消耗默认视野。
每个字段只出现一次如果它已经在标题栏或生命体征带里，正文就不再重复。
生命体征带字段按 kind 定义Pod：status / ready / restarts / age / node / ip。Deployment：rollout / ready / up-to-date / available / strategy / age。Node：status / roles / version / cpu / mem / pods。骨架不变，字段表随 kind 切换。
宽度断点 760px之上两栏，之下单栏且元数据折叠。集成分栏模式下 Detail 面板通常在断点以下。

实现侧全部是 egui 原生件：生命体征带 = Frame + 横向 Grid；KV 区 = egui::Grid（striped(false)，hover 整行高亮）；labels = ui.horizontal_wrapped 里的圆角 Frame；折叠区 = CollapsingHeader；两栏 = ui.columns(2, …) 并在 available_width() < 760.0 时退化为单栏。
