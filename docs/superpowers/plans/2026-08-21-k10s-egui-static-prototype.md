# k10s egui Static Prototype Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a native, static-but-interactive egui prototype of the approved k10s console using realistic mock Kubernetes data and no live cluster connection.

**Architecture:** `K10sApp` owns pure domain and workspace state, then delegates rendering to focused `ui` modules. Window instances are explicit state records keyed by stable IDs; resource windows reuse a generic list/detail shell and dispatch kind-specific tables and details. Logs, shell, YAML edits, mutations, loading, errors, and context changes are deterministic simulations so every approved interaction can be exercised without Kubernetes infrastructure.

**Tech Stack:** Rust 1.95 / edition 2024; exactly pinned `eframe`/`egui` 0.36.1; `egui_extras` 0.36.1 tables; `egui_kittest` 0.36.1 for AccessKit interaction and image snapshots; standard-library collections only.

---

## Scope and boundaries

This plan implements the UI prototype defined in `docs/superpowers/specs/2026-08-21-k10s-egui-console-design.md`.

- Native desktop only.
- Mock contexts and resource data only.
- Logs append deterministic mock lines; Shell uses a local transcript and never executes commands.
- Scale, restart, delete, run-now, suspend, and YAML apply update simulated state only.
- The code exposes boundaries that a future Kubernetes data source can implement, but this plan does not add `kube`, Tokio, authentication, networking, or process execution.

- `Cargo.toml`: package metadata and pinned egui dependencies.
- `rust-toolchain.toml`: Rust 1.95 toolchain with Clippy and rustfmt.
- `kittest.toml`: deterministic snapshot output and strict pixel tolerances.

- `src/lib.rs`: public module graph and `K10sApp` export for tests.
- `src/app.rs`: application construction, frame composition, and top-level event application.
- `src/theme.rs`: restrained default-egui style adjustments and status colors.
- `src/model.rs`: contexts, resource identities, workload kinds, rows, details, and mock operation types.
- `src/mock.rs`: deterministic fixture contexts, resources, YAML, logs, events, and shell transcript.
- `src/workspace.rs`: window registry, IDs, focus/MRU behavior, context-switch guards, and dedicated-detail ownership.
- `src/ui/mod.rs`: rendering module exports and shared UI helpers.
- `src/ui/top_bar.rs`: menus, connection status, refresh, and context switch.
- `src/ui/launcher.rs`: fixed left launcher, workload group, highlight/count/plus behavior.
- `src/ui/overview.rs`: Overview summary and attention table.
- `src/ui/infrastructure.rs`: Nodes and Storage singleton windows.
- `src/ui/resource_window.rs`: generic resource list window and integrated split detail.
- `src/ui/detail.rs`: kind-specific Overview/Pods/Events detail tabs and dedicated detail window.
- `src/ui/tools.rs`: YAML, Logs, and Shell tabs.
- `src/ui/dialogs.rs`: simulated mutation and navigation-guard dialogs.
- `tests/workspace_state.rs`: pure window-state and context-switch tests.
- `tests/resource_state.rs`: owner-chain, selection, YAML, shell, and mutation tests.
- `tests/app_smoke.rs`: crate construction and initial-state smoke test.
- `tests/ui_harness.rs`: AccessKit interaction tests for launcher and hybrid detail behavior.
- `tests/ui_snapshots.rs`: fixed-size visual snapshots of the approved screen set.
- `tests/snapshots/`: checked-in reference PNGs generated by `egui_kittest`.
- `README.md`: run, test, snapshot, scope, and interaction documentation.

let mut open = true;
egui::Window::new(title)
    .id(egui::Id::new(("window", instance_id)))
    .open(&mut open)
    .default_pos(staggered_position(instance_id))
