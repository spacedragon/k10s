# Destructive Review and Window-state Accessibility Design

Issue #171 refines two existing UI seams rather than introducing new protocol behavior. The delete dialog continues to consume the authoritative `DestructivePreflight` produced by the application/client command path. Its presentation becomes a compact numbered sequence: exact scope, impact and propagation, server dry-run, typed confirmation, and the equivalent command. Submission remains derived only from connection, freshness, successful preflight, exact typed input, and single-consumption state. Enter is accepted only while the confirmation field owns keyboard focus and those same gates pass, preventing an unrelated Enter key from triggering deletion.

Window resilience remains a per-`WindowId` projection in `ResourceFeed`. The existing lifecycle gains explicit reconnecting and filtered-empty presentations, and each non-live state renders a bordered status card with an icon/shape, status text, explanation, and recovery guidance. Recovery availability is carried by the projection so Retry and Full resync remain discoverable but visibly and accessibly disabled when the client cannot accept them. Production still creates projections from client lifecycle and recovery eligibility; tests inject the public presentation projection, never a fake-only protocol shortcut.

Accessibility is verified at two levels. Token contrast tests cover normal, muted, selected, focus, status, and disabled colors against their actual surfaces. AccessKit snapshots cover every lifecycle plus delete confirmation at fixed compact and standard viewports, including disabled controls and their reasons. Pixel screenshots use the same deterministic egui fixtures and fixed viewport sizes, producing reviewable before/after evidence committed under `docs/screenshots/issue-171/`.

Alternatives considered were deriving reconnecting/disabled state directly from the global connection inside widgets, and building a separate showcase-only UI. The former would regress window independence; the latter would violate the delivery contract by allowing fake-only presentation drift. Extending the existing projection is the smallest approach that preserves ownership and makes every state deterministic.
